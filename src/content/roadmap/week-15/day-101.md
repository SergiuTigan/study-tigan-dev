# Day 101 — Frontend Scaffold (Project #2)

> *"Every project should look different but feel like the same engineer built it."*

**Date:** Wednesday, 27 August 2025
**Hours:** 2h · Evening session
**Topic:** Frontend Pages, Components & Layout
**Phase:** Faza 4 — Portfolio + Job Hunt · Week 15

---

## What You're Doing

Build the frontend for Project #2. Same approach as Day 94 — layout, pages, components, styling — but with a different design direction. Your two projects should be visually distinct so your portfolio shows range, not repetition.

## The Work

### 1. Choose a Different Layout Pattern (10 min)

If Project #1 was a full-width chat interface, try:
- **Dashboard layout** — sidebar navigation, cards, data displays
- **Wizard/step-based** — multi-step form or guided experience
- **Split-pane** — input on left, output on right

### 2. UI Setup (15 min)

```bash
npx shadcn@latest init
npx shadcn@latest add button input card textarea tabs badge separator
```

Pick different shadcn components than Project #1. If you used chat bubbles before, use cards and tables now.

### 3. Build Pages (50 min)

Build based on your wireframes:
- **Main interaction page** — different structure than Project #1
- **Results/output page** — how do you display AI results? (Cards? Tables? Timeline?)
- **Landing page** — brief, compelling, different style

### 4. Build Components (30 min)

Focus on project-specific components:
- Input components (forms, file upload, multi-step inputs)
- Output components (result cards, data visualizations, summaries)
- Status components (progress bars, step indicators)
- Navigation components (tabs, breadcrumbs)

### 5. Styling & Visual Identity (15 min)

Make it visually distinct from Project #1:
- Different primary color
- Different layout structure
- Different component patterns
- Same level of polish (or better)

## Tips for Efficiency

- **Don't start from scratch on shared patterns.** Copy your layout wrapper, loading states, and error components from Project #1.
- **Use a different shadcn theme.** Change the CSS variables for a fresh look with zero effort.
- **Placeholder data is mandatory.** Build the UI with fake data so you can see the layout working.

## Key Insight

Visual diversity in your portfolio matters more than you think. A recruiter scrolling your GitHub should see three distinct-looking projects. Same quality, different personality. This tells them you can adapt to any product's design needs.

## Done When

- [ ] Layout built with a different structure than Project #1
- [ ] Main interaction page complete with placeholder data
- [ ] All components render without errors
- [ ] Responsive at mobile, tablet, and desktop breakpoints
- [ ] Visually distinct from Project #1
- [ ] Looks like a product, not a clone of your first project
