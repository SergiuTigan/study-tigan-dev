## What You're Doing

Same structure as Day 97. Polish, edge cases, deploy. But the bar is higher this week. Project #2 should feel more refined than Project #1. You have the same 4 hours — you'll use them better because you've done this before.

## The Work

### Hours 1-2: Polish (120 min)

Apply everything you learned from polishing Project #1:

**Visual Consistency**
- [ ] Design language is coherent (spacing, colors, typography)
- [ ] AI outputs are well-formatted (markdown rendering, code blocks, lists)
- [ ] Empty/loading/error states all have proper UI
- [ ] Transitions are smooth between states

**The Complex Pattern Polish**
This is unique to Project #2. If you're using RAG, tools, or agents:
- [ ] Source citations displayed clearly (if RAG)
- [ ] Tool execution visible to user (if tools)
- [ ] Agent progress shown step-by-step (if agents)
- [ ] Processing time shown or estimated
- [ ] Intermediate results formatted well

**Responsive**
- [ ] Mobile: functional, not just "doesn't break"
- [ ] Desktop: uses the space well
- [ ] Test on actual phone if possible

### Hour 3: Edge Cases (60 min)

All Project #1 edge cases plus:
- [ ] Large dataset/document handling (if RAG)
- [ ] Tool timeout handling
- [ ] Agent loop protection (max iterations)
- [ ] Concurrent request handling
- [ ] Session state persistence

### Hour 4: Deploy (60 min)

```bash
npm run build  # Fix any build errors
npx vercel --prod
```

**Post-deploy verification:**
- [ ] All environment variables set in Vercel dashboard
- [ ] AI features work in production
- [ ] Complex pattern works with production data
- [ ] Performance acceptable (< 5s for main interaction)
- [ ] No console errors
- [ ] OG meta tags for social sharing

## Tips for Efficiency

- **Use Project #1's deploy config as a template.** Same Vercel setup, same env var pattern.
- **Test the demo flow 5 times end-to-end in production.** That specific flow must be bulletproof.
- **If something is broken and you can't fix it in 20 min, hide it.** A feature that's missing is better than a feature that's broken.
