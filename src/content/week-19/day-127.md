## What You're Doing

Practice designing AI systems from scratch — the way an interviewer would ask. This is different from building projects because you need to think out loud, discuss tradeoffs, and make decisions with incomplete information. You've built these systems. Now learn to explain them under pressure.

## The Work

### The Framework (15 min)

Memorize this approach for any LLM system design question:

**1. Clarify Requirements (2-3 min)**
- Who are the users?
- What's the scale? (queries/day, data size)
- What's the latency requirement?
- What's the budget?
- What quality bar? (accuracy, consistency)

**2. High-Level Architecture (5 min)**
- Draw the major components
- Show the data flow
- Identify the AI touch points

**3. Deep Dive on AI Components (10-15 min)**
- Model selection (which LLM and why)
- Prompt design
- Context management (RAG, memory, tools)
- Output processing

**4. Production Concerns (5 min)**
- Monitoring and evaluation
- Cost optimization
- Scaling strategy
- Failure modes and recovery

**5. Tradeoffs Discussion (5 min)**
- What are the alternatives?
- What did you sacrifice for what you gained?
- What would you change at 10x scale?

### Practice Problems (105 min — ~25 min each)

**Problem 1: Design a RAG-Based Customer Support System**
- 10,000 queries per day
- Knowledge base of 5,000 support articles
- Must cite sources
- Sub-3-second response time
- Handle escalation to human agents

*Key decisions to discuss: embedding model, chunk strategy, vector store, reranking, fallback behavior, escalation triggers.*

**Problem 2: Design an AI Code Review Agent**
- Reviews PRs automatically
- Provides suggestions, catches bugs, checks style
- Integrates with GitHub
- Must not block CI/CD if it fails
- Handles multiple programming languages

*Key decisions to discuss: how to provide code context, model selection per task, tool use for running tests, confidence thresholds for suggestions vs. blocking.*

**Problem 3: Design an LLM Evaluation Pipeline**
- Evaluate a chatbot across 500 test cases
- Track quality over time
- Detect regressions when prompts change
- Generate human-readable reports
- Budget: $50/month for eval runs

*Key decisions to discuss: LLM-as-judge vs. human eval, test case generation, metric selection, regression detection, cost management.*

**Problem 4: Design a Multi-Model Cost Optimization System**
- Route queries to different models based on complexity
- GPT-4o for complex, GPT-4o-mini for simple
- Must maintain quality while reducing cost
- Track cost per query and quality per model

*Key decisions to discuss: classification approach, quality metrics, routing logic, fallback to expensive model, A/B testing.*

### For Each Problem:

1. Set a 25-minute timer
2. Whiteboard or write out your design (paper, iPad, Excalidraw)
3. Talk through it out loud as if explaining to an interviewer
4. Note where you got stuck or uncertain
5. Review and fill knowledge gaps

## Key Insight

You've actually built most of these systems during Faza 2-3. The interview version isn't about writing code — it's about articulating decisions. "I chose Pinecone over pgvector because X" or "I'd use GPT-4o-mini for routing because Y" — these are the sentences that win system design interviews.
